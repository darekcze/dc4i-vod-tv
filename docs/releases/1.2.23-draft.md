# 1.2.23 draft — offline DVR scheduling contracts (not released)

Canonical issue #23, stacked on #22. Production remains1.2.19. No real recording
backend or storage was selected, configured, probed or written. No provider/LG,
network setup, persistent permission or file-recording operation occurred.

The dependency-free scheduler accepts explicit future UTC jobs, opaque IDs,
channel IDs and estimated byte budgets. IDs are idempotent (including after
start); mismatched reuse is rejected. A half-open interval sweep checks actual
simultaneous conflicts, with bounded job/concurrency/quota limits. Uncertain
start/finish/cancel failures retain reservations and block new jobs pending
reconciliation. Late jobs are marked missed rather than inventing full captures.

Only tests inject an in-memory backend. Explicit ticks (no automatic scheduler)
exercise start/finish/cancel/stat, deadlines and generation guards. Cancel waits
for pending operations, then requires confirmation. A future real adapter must
honor idempotent job IDs and cancellation of pending work; synthetic tests do not
prove device cleanup. Transport errors become generic codes; backend requests
and snapshots whitelist metadata, never credentials or playback/storage URLs.

Versioned snapshots remain caller-owned memory data; this module persists
nothing. Recovery is atomic, refuses to overwrite an existing job set, changes
in-flight jobs to interrupted and never resumes them automatically. Reconciliation
can confirm only artifact metadata. Every returned job has playable:false and
capability.usable is always false, even with the fake backend. Retention produces
an eligible-item plan, never deletes data. Simulation quota defaults are policy
fixtures, not a selected real disk or storage allocation.

The app loads an informational PL/EN DVR availability setting only. There is no
backend, record action, schedule UI, recording timer or required server. Ordinary
Home/guide/live viewing remain independent. The setting uses the existing in-app
toast, not a native/background notification.

## Acceptance gaps
- Backend/storage choice, capture/codec/rights and quota measurements: not authorized/verified.
- Actual recording bytes, crash-safe persistence, restart and playback: not implemented/verified.
- Real scheduling/recording UI stays hidden until authorized usable capability exists.
- Browser1920x1080/remote/performance QA, production package/catalog/deployment and
  applicable LG acceptance remain gated. Earlier source/browser gates remain open.

Tests: test_dvr_scheduler.mjs covers conflicts, quotas, idempotency, cancellation,
failures, deadlines, retention plan, snapshots/recovery and late-result guards.
Test backend holds metadata in a Map, not media files. test_dvr_integration.mjs
executes generated settings routing and checks no record/schedule action exists.
No merge/deployment or paid service is introduced.
