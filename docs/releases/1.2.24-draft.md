# 1.2.24 draft — foreground reminders (not released)

Canonical issue #24. Production remains1.2.19. The existing future-programme
Details/search entrypoint now delegates to one reminder model; its old cached
list/timer is removed. No parallel reminder system is introduced.

The existing per-profile dc4iEpgRemindersV1 array stays compatible. Valid legacy
entries and unknown fields/records are preserved; no migration or key rename.
New admission is bounded to100 entries/30 days, while larger legacy lists are
not truncated. Reminders deduplicate by channel+UTC start; cancellation removes
only the chosen key. Expiry uses the existing five-minute grace window.

A new profile-scoped dc4iReminderPrefsV1 stores enabled/quiet preferences. Quiet
hours use local TV time, support overnight intervals, and equal endpoints mean
all day. UTC event identities distinguish repeated DST wall-clock times; no
nonexistent local time is invented. Quiet/closed-app reminders that expire are
not replayed later. Disabling reminders preserves pending entries until enabled.

Delivery requires document visibility AND focus; unknown/hidden/unfocused state
cannot deliver. One in-app toast summarizes due reminders; no native system toast,
background task, wake API or permission. Checks run each minute and on focus/
visibility changes. Storage removal must be confirmed before delivery, preventing
repeated notifications after reload. Failed writes do not claim saved/cancelled
or delivered; invalid preferences pause notifications. A crash between confirmed
removal and toast can lose delivery: foreground delivery is best-effort, not an
exactly-once background guarantee.

Remote settings expose enable/quiet controls, start/end hours (left/right or OK),
a profile reminder list and per-entry cancellation. PL/EN copy describes the
foreground limitation. Lists render at most100 controls without deleting overflow;
all mutations reread current profile storage rather than retaining a stale array.

Tests cover legacy preservation, profile isolation, reload/deduplication,
failed writes, quiet-hour boundaries, both DST transitions, UTC identities,
expiry/cancel, visible+focused gate, remote controls and generated integration.
No provider data or real TV/native-background test is used.

Remaining gates: independent review, real browser1920x1080/remote/profile-reload
and webOS visibility/focus behavior, production package/catalog/deployment and
applicable device acceptance. Native background capability remains unverified
and disabled. No merge, release, paid operation, new credentials or security change.
