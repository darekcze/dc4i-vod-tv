## Home integration increment
The build now loads the model/UI. New rows precede existing catalogue rows;
the old personalized row returns when custom sections are disabled. Settings
opens a remote-operated section list: OK toggles, left/right reorders, Back
returns. Order/enabled state and metadata cache use existing profile-scoped
TV.store keys. Profile selection still reloads via the existing profile feature.
No playlist/history/settings migration is introduced.

Cold cached rows render without a live base catalogue, with the empty hero
excluded from remote focus. Stale and unknown freshness are labeled; expired or
corrupt cache produces a navigable empty-state card opening configuration.
Original loaded TMDB art may be reused, but no art is invented for cache-only
cards. Canonical title cards open existing Details; airing cards only explain
metadata and never invoke playback. Existing profile ranking settings still apply.

Tests additionally cover actual built store namespace behavior, cold render hooks,
remote settings/order actions, profile restore, empty/stale/expired states,
chronological boundaries, spring/autumn DST, 300-item cap, future/corrupt cache
and unavailable/cleared storage. New tests: test_home_ui.mjs and
 test_home_integration.mjs. Real layout, remote navigation and performance remain
unverified until the browser environment is repaired; no LG operation is authorized.
