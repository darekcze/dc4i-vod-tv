# 1.2.27 draft — bounded preferences backup and storage audit (not released)

Production remains 1.2.19. This is partial canonical #27, not runtime or release
acceptance. The basic single-section text export/import includes ONLY Home layout, reminder
preferences and official-chart region/category. No accounts, credentials,
playlists, history, titles, streams, caches or arbitrary storage enumeration.
Export copies only fixed allowed fields; unknown/private fields are omitted.
Import rejects unknown sections/fields, schema changes and inputs over16KiB.

User pastes JSON, selects one section, validates/previews, then applies. Editing,
closing or selecting another section invalidates preview. Apply compares current
raw value and profile with preview to reject concurrent/profile conflicts. One
localStorage key is written per operation; existing unknown destination fields
are preserved. Undo is in-memory, same session/profile and only if the imported
value remains unchanged. The basic workflow has no multi-key atomic restore or crash-persistent rollback;
the expanded journaled workflow below is separate. Copy exported text before leaving to retain a backup.
Writes require readback; unconfirmed writes are reported as such, not success.

Storage audit: Home layout fails closed and refuses writes when unreadable;
Home metadata cache degrades to missing without suppressing live data. Opened
history no longer overwrites malformed/unreadable data on title open; explicit
clear confirms write. Guide rereads preferences on show, blocks writes over
unreadable fields and confirms favorites writes before changing their UI state.
Existing strict reminder/chart/playback readers remain. Unreadable general
profile settings disable new learning/personalization and block settings writes
instead of silently replacing corrupt values with defaults. Legitimate absent
keys retain first-use defaults. No account/profile/playlist migration is run.

Bounds: synthetic Home test uses2000 titles/20000 EPG events for five rebuilds,
max20 cards/row, max11 rows, cache cap300 and oversized-cache rejection. Existing
media tests verify listener rebind/cleanup and profile/clear boundaries. These
are Node measurements, not TV performance or an overnight soak. Real browser,
remote input/textarea, storage quota/reload, LG memory/long-run and live-source
behavior remain unverified. See the canonical20–27 acceptance matrix.

Rollback: drafts are unmerged and production unchanged. For local preference
import use same-session Undo before changing profile/section value; otherwise
preview/import a previously exported allowed section. Corrupt data is preserved
for authorized recovery, never automatically cleared. Actual release rollback
must use a previously verified matching manifest/IPK deployment, preserve app ID
and user data, and remains a future release gate. No secrets, TV access, sandbox
changes, real DVR storage selection, merge or deployment performed.

Import preview now shows sanitized before/after values, unchanged markers and
missing/invalid states; raw invalid or unknown fields are never displayed.
See docs/STACK-VERIFICATION.md for pinned checkpoints and safe commands.

## Expanded v2 metadata restore

The additional v2 flow exports fixed profile preferences and title-free opened /
playback metadata alongside the three basic sections. Profile language and
recommendation preferences use enums/booleans/rating limits. Histories contain
canonical numeric TMDB identities or local session IDs, times, genre IDs and
observed-duration metadata, never titles, streams, accounts or credentials.
Unknown local fields are omitted from export and preserved in destination data.
Imported playback records are marked imported and excluded from native-progression
learning; a backup is not proof of observed playback.

Preview shows the sanitized before/after metadata. Existing history records are
preserved and imports add only new identities; duplicate legacy entries remain
local. A merge exceeding150 records is rejected rather than truncating history.
Input limit256KiB; journal limit512KiB; at most6 sections. Supported schema1
preference exports migrate explicitly to schema2; unknown schemas are rejected.
This is synthetic, documented schema migration, not an executed production migration.

Multi-section restore requires browser Web Locks. If unavailable it is disabled,
with truthful feedback. It writes an allowlisted metadata journal before any
section. Each localStorage write is atomic, but the batch is NOT a globally atomic
transaction. On interruption, a reconstructed controller rolls back uncommitted
steps; a committed journal only needs cleanup. Failed rollback leaves the journal
for explicit recovery. Profile changes and conflicting allowed-field edits block
mutation. Unknown concurrent fields are preserved. Non-cooperating external writers
are not covered by a cross-context transaction guarantee; conflicts require review.

Unresolved journals block affected ordinary readers/writers and new imports until
explicit recovery, preventing partial settings from driving reminders/learning.
The recovery port is separately restricted to the6 metadata keys plus journal.
Browser UI offers explicit recover, not silent deletion. General settings save now
also rejects a changed baseline, protecting imports from a stale settings draft.
Quota/interruption tests cover every apply write and rollback reconstruction,
committed cleanup, corrupt journals, profile switches, conflicts, capacity limits
and250 repeated native listener bind/cleanup cycles.

while invalid existing partial chart storage is rejected and preserved.
