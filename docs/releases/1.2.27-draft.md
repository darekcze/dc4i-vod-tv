# 1.2.27 draft — bounded preferences backup and storage audit (not released)

Production remains 1.2.19. This is partial canonical #27, not runtime or release
acceptance. In-app text export/import includes ONLY Home layout, reminder
preferences and official-chart region/category. No accounts, credentials,
playlists, history, titles, streams, caches or arbitrary storage enumeration.
Export copies only fixed allowed fields; unknown/private fields are omitted.
Import rejects unknown sections/fields, schema changes and inputs over16KiB.

User pastes JSON, selects one section, validates/previews, then applies. Editing,
closing or selecting another section invalidates preview. Apply compares current
raw value and profile with preview to reject concurrent/profile conflicts. One
localStorage key is written per operation; existing unknown destination fields
are preserved. Undo is in-memory, same session/profile and only if the imported
value remains unchanged. There is no multi-key atomic restore, automatic migration
or crash-persistent rollback. Copy exported text before leaving to retain a backup.
Writes require readback; unconfirmed writes are reported as such, not success.

Storage audit: Home layout fails closed and refuses writes when unreadable;
Home metadata cache degrades to missing without suppressing live data. Opened
history no longer overwrites malformed/unreadable data on title open; explicit
clear confirms write. Guide rereads preferences on show, blocks writes over
unreadable fields and confirms favorites writes before changing their UI state.
Existing strict reminder/chart/playback readers remain. Unreadable general
profile settings disable new learning/personalization and block settings writes
instead of silently replacing corrupt values with defaults. Legitimate absent
keys retain first-use defaults. No account/profile/playlist migration is run.

Bounds: synthetic Home test uses2000 titles/20000 EPG events for five rebuilds,
max20 cards/row, max11 rows, cache cap300 and oversized-cache rejection. Existing
media tests verify listener rebind/cleanup and profile/clear boundaries. These
are Node measurements, not TV performance or an overnight soak. Real browser,
remote input/textarea, storage quota/reload, LG memory/long-run and live-source
behavior remain unverified. See the canonical20–27 acceptance matrix.

Rollback: drafts are unmerged and production unchanged. For local preference
import use same-session Undo before changing profile/section value; otherwise
preview/import a previously exported allowed section. Corrupt data is preserved
for authorized recovery, never automatically cleared. Actual release rollback
must use a previously verified matching manifest/IPK deployment, preserve app ID
and user data, and remains a future release gate. No secrets, TV access, sandbox
changes, real DVR storage selection, merge or deployment performed.
