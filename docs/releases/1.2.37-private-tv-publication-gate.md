## User-visible features verified and scope

- On LG, owner confirmed CH+/CH- and Magic Remote pointer working in 1.2.34. 1.2.35 included additional preventive fixes for ambient overlay and native fullscreen video.
- Private 1.2.36: HBO Max from DC4I VODTV launched installed app ID `com.wbd.stream`; LG reported that app in foreground. No particular HBO title or login success was claimed.
- Private 1.2.37: application-side resolver checked `com.wbd.stream` (HBO Max), `canalplus` (CANAL+) and `com.skyshowtime.tv` (SkyShowtime) on actual LG. Existing local IPTV account still present.
- Owner-side installed-app scanner matched all seven configured provider app IDs. TV app's ordinary webOS privilege cannot list all installed apps: a direct `listApps` call returned a denial, so the resolver checks known IDs via `getAppLoadStatus`.
- IPTV ambient slideshow: a normally running video stays exempt. On paused/stopped/error or explicitly stalled low-readiness video, or a static guide screen, an inactivity period of 120 seconds is eligible. The implementation does not analyze actual pixels/frames; a static-looking video whose media clock still progresses is deliberately treated as playing. Overlay release on pointer/key input and on resumed playback is implemented.
- Deterministic unit/media-state tests, JavaScript syntax and webOS packaging checks passed. A timed real-TV pause/stall hardware endurance test is still outstanding.

## Explicit blocking prerequisite: upstream copyright

The code includes parts derived from `theboringhumane/theboringtv-lgwebos` at the pinned `UPSTREAM.lock` source SHA. On 2026-10-30, the upstream repository did not contain a repository-wide `LICENSE` file and its README only credits a separately MIT-licensed third-party component. A publicly readable GitHub repository does **not** confer rights to redistribute that upstream code as a public DC4I IPK or derived source.

- Blocker: [issue #4](https://github.com/darekcze/dc4i-vod-tv/issues/4).
- Required: explicit permission for redistribution and public modifications from relevant rights holders **or** a clean-room replacement of portions without such permission.
- Retain license/NOTICE files and third-party attribution after the license audit. Do not apply a new license retroactively to upstream-owned portions.

## Publication checklist after prerequisite is cleared

1. Reconcile the full private 1.2.37 source into version-controlled source history. It was derived from the exact installed app, **not** a simple commit on the old `main` 1.2.19 tree. Do not take the 1.2.19 build, rename it 1.2.37, or force-merge multiple feature drafts.
2. Exclude secrets and user data: no `keys.js`, IPTV URLs, usernames/passwords, playlists, localStorage dumps, TV SSH keys or session tokens in Git history, deployment logs or distributable package beyond carefully scoped public API credentials. Audit embedded TMDB/API key exposure in the public IPK.
3. Validate provenance of every distributable asset, library and upstream component, including non-code artwork.
4. Run all guide, EPG, input, TV/browser and catalog regression tests. Test 2-minute paused/stalled media behavior on the actual LG and confirm the remote regains focus after slideshow dismissal. Test clean install, in-place upgrade, account retention and rollback.
5. Produce a reproducible, single-version source commit and binary IPK; check IPK app id `com.dc4i.vodtv`, version `1.2.37`, SHA-256, file size and signatures.
6. Preserve 32 other Homebrew/DStore entries. **Never** publish a manifest that references a not-yet-uploaded IPK. Upload the verified package to Cloudflare Pages first, check a public HTTP 200 download and remote SHA-256. Then update `/manifests/dc4i-vodtv.manifest.json`, `/api/apps.json`, root JSON, and browser catalog in one deployment.
7. Update GitHub `main` source, tags, English/Polish changelog and deployment evidence, then verify Cloudflare Pages URLs, catalog version and IPK hash from outside the deployment environment.
8. Include rollback to 1.2.19 only if compatible with existing user data; do not advise uninstalling 1.2.37 or resetting accounts.
